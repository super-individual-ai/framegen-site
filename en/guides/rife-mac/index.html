How to use RIFE for real-time interpolation on Mac

Updated November 14, 2026 · OpenDuckFrame 0.6.2 · 中文版

OpenDuckFrame offers ODF-VFI, a four-stage reduction of RIFE 4.25 that runs through Metal on Apple silicon to create intermediate pictures for windows, displays or local video. The app requires macOS 14 or later. Select ODF-VFI, begin with fast quality and X2, then compare observed output and motion.

How ODF-VFI relates to RIFE

ODF-VFI is a structural reduction of RIFE 4.25: one stage is removed, the four retained stages keep the upstream weights, and no new training is applied, so model processing overhead is lower. It does not guarantee identical quality in every scene. Frame generation does not automatically increase resolution.

The workbench also offers Apple low latency and Apple FRC. On supported macOS 26+ devices, new and reset profiles use Apple low latency X2; other devices use ODF-VFI fast X2. Saved engine choices are preserved. Continuous caching remains on without a separate switch.

Start with one controlled comparison

  1. Open File → Quality Workbench (⇧⌘E) and select a window, display or video file.
  2. Select ODF-VFI, fast quality and X2. Leave scaling off so this comparison changes only interpolation.
  3. Select a window and press Enhance Selected Window, or use Delayed enhancement. For displays and files, press Start enhancement. Live capture needs Screen Recording permission.
  4. Compare the picture before and after. Inspect the FPS panel, subtitles and moving edges, then save a profile. Recheck when raising quality or rate.

A multiplier is a request, not observed FPS

X2 / X3 / X4 request a processing mode. For example, 24 fps × 2 targets 48 fps in theory. Source timestamps, resolution, quality, frame budget and display refresh rate still constrain actual presentation. A 60 Hz display cannot present 120 different pictures per second.

Live target-FPS mode reuses source pictures and interpolates remaining slots according to source timestamps. Jobs that miss their output budget may be skipped; repeated pictures do not count as new motion. Multiplier mode also adjusts the effective multiplier to the processing budget and display refresh rate. Check the picture actually presented.

Live sources and local files use different paths

Windows and displays use ScreenCaptureKit; local files use the player’s decoding path. Continuous caching is on by default and has no separate switch. File playback bounds the time spent waiting for inference by the available playout runway and output interval. Late synthetic frames can be discarded with original-picture fallback; this does not guarantee the requested multiplier on a slower Mac.

When output falls behind or looks unnatural

  • Return to X2, lower the source resolution or choose a lighter quality mode. Change one setting at a time.
  • Protected content may not be capturable. Reselect the source after problematic resizing, fullscreen transitions or occlusion.
  • Interpolation can add latency or create motion artifacts. Compare the original picture before enabling it for latency-sensitive use.
  • For a reproducible report, record the Mac, macOS and app versions, source size and rate, frame-generation model and quality, requested rate, display refresh rate and observed output.

This page makes no cross-device speed or quality promise and does not treat a demo animation as a benchmark. See the interpolation guide for capture setup or the upscaling guide for picture resizing.
